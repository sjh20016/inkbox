# 《坐天观井 · UX/QoL 玩家体验填缝包 v1》

## 一、任务定位

本轮不是新阶段主线开发，也不是视觉升级。

目标是：

> 在不修改核心模拟规则、不扩张大型系统、不进行复杂视觉制作的前提下，通过一系列小型交互、反馈、导航、存档安全和信息呈现改进，让当前《坐天观井》从“功能已经很多”进一步变成“玩家能顺畅地使用这些功能”。

当前仓库基线以 main 最新代码为准。

已知当前状态：

- D6-2 / D6-3 三界生态与跨界生态已经完成。
- D7 A–G 已完成。
- D8 A–F 已完成。
- Render3D M0 → M2-C2C 已形成正式底座。
- C2C Meaningful Geography 已完成本地验收。
- 现有玩家功能已经包括四档观察尺度、修士检视、宗门、战争线、关系图、记挂、编年史、卜算子、新手引导、视界、地形编辑、存读档、导入导出、三界面板等。
- 本轮应优先改善“已经存在的功能如何被玩家使用”。

本轮原则：

**不造新的大系统，只让已有系统之间开始互相说话。**

---

# 二、禁止事项

本轮不得顺手进行以下施工：

1. 不修改三界生态概率、数值和平衡。
2. 不修改 RNG 流。
3. 不重构 `save.js` schema。
4. 不重写 `planes.transfer()`。
5. 不建设 D8-G 跨界追迹正式 UI。
6. 不建设道路 / A* / 寻路。
7. 不增加幽冥城市、上界文明、第四世界等大型玩法。
8. 不重写 renderer、shader、LOD、HLOD、Stage 或 Bridge 架构。
9. 不进行大规模 CSS / UI 重新设计。
10. 不生产新 GLB、美术资产或复杂动画。
11. 不为了“顺手清理”修改模拟逻辑。
12. 不添加重量级框架或依赖。
13. 不建立第二套事件、选中、历史、存档或世界状态。
14. 不要求重新跑大型 Golden Screenshot 矩阵作为本轮主要验收方式。

如果某项小改需要触碰以上内容，暂停该项，继续执行其他任务。

# 三、第一组：立刻消除玩家操作摩擦

## Q1 · Escape 行为改成分层关闭

当前目标：

Escape 不应成为含义模糊的“什么都关”按钮。

建立统一的 Escape 优先级：

弹窗 / 帮助层
→ 临时关系图等浮层
→ 当前视界
→ 当前临时选区
→ 当前检视
→ 无操作

原则：

- Escape 不重置世界。
- Escape 不修改模拟。
- Escape 不误触“重新开天”。
- Escape 不改变当前时间速度。
- 连续按 Escape 可以逐层退回普通观察状态。

验收：

自动构造多个 UI 状态，逐次发送 Escape，检查每次只关闭最上层状态。

复杂度：XS

优先级：最高。


## Q2 · 键盘快捷键输入框保护

统一检查全局快捷键。

当焦点位于：

- seed 输入框
- 数字输入
- 文本输入
- select
- textarea
- contenteditable

时：

`1–6 / G / V / W / H / [ / ] / Space`

不得误触游戏快捷键。

Escape 可以按既定规则处理。

验收：

focus seed 输入框 → 输入数字 → 时间速度不变化。

复杂度：XS。


## Q3 · 所有“不允许执行”的工具必须告诉玩家为什么

现在很多沙盒游戏最糟糕的手感不是报错，而是“点了什么都没发生”。

统一给这些情况增加明确反馈，例如：

- 视界打开时尝试雕刻凡间。
- 当前目标不可施加该神力。
- 没有可撤销操作。
- 当前点击位置不存在合法对象。
- 某操作只允许凡间。
- 某操作需要先选择人物 / 宗门。
- 当前窗口状态阻止该操作。

反馈优先复用现有 Toast / 提示机制。

不要新增 modal。

推荐格式：

`此时不能平整地形 · 先关闭视界`

而不是：

`操作失败`

验收：

主要工具的非法路径不得静默失败。

复杂度：S。


## Q4 · 工具不可用时同步 disabled 状态

不仅仅在点击后告诉玩家。

如果某工具当前明确不可用：

- 按钮进入 disabled / unavailable 状态。
- hover/title 说明原因。
- 条件恢复后自动恢复。

重点处理：

- 视界打开时的地形编辑。
- 无撤销栈时的撤销。
- 无选中对象时依赖选中的按钮。
- 空存档槽的读档。
- 没有活动战争时某些战争相关入口。

不得复制业务判断。

UI 必须调用现有状态或现有 guard。

复杂度：S。


## Q5 · 当前工具增加持续状态提示

玩家应该随时知道“自己手里现在拿的是什么”。

利用现有顶部/底部工具区增加一个非常轻的状态：

`检视`
`抬山 · 12`
`平滑 · 8`
`上界视界`
`幽冥视界`

数字可以是笔刷尺寸。

不要增加新的大型 HUD。

工具切换、快捷键切换和程序切换必须同步。

复杂度：XS。


## Q6 · 时间速度反馈统一

已有 1–6 时间档位。

补齐：

- 当前档位始终有选中状态。
- 键盘切档与 UI 按钮完全同步。
- 暂停必须有明显文字状态。
- 使用快捷键切速时给一次轻量反馈。

示例：

`岁月 · 疾`
`岁月已停`

避免每个游戏 tick 重复提示。

复杂度：XS。


## Q7 · 撤销状态完整化

现有 Ctrl+Z 与地形撤销已经存在。

补：

- 没有历史时按钮 disabled。
- 成功撤销后提示一次。
- 当前状态禁止编辑时，不要让撤销表现得像可以使用。
- Ctrl+Z 与按钮共用一条执行路径。

不要创建第二套 undo。

复杂度：XS。


## Q8 · 正式视界增加明确“关闭视界”入口

现在玩家可以切回检视关闭视界，但这属于“知道规则以后才知道怎么关”。

视界打开后，在已有视界状态附近提供：

`关闭视界`

它只调用现有关闭逻辑。

不得创造新的 selection 状态。

Canvas 与 Three 共用同一 RealmViewState 语义。

复杂度：XS。

# 四、第二组：让信息真正可以“点进去”

这一组预计是整轮体验收益最高的部分。

当前 Inkbox 已经拥有大量信息，但不少仍然像博物馆标签，只能看，不能顺着线索继续探索。

目标是把“文本”变成“入口”。


## Q9 · 列表中的人物姓名尽量可点击

审查已有 UI：

- 飞升名册
- 魂池
- 归来人物
- 宗门成员
- 记挂列表
- 战争相关人物
- 关系信息
- 其他已经携带真实 entity id 的列表

只要条目已经拥有权威 entity id：

点击姓名应该复用现有：

`inspect → focus`

或者只 `inspect`，视当前组件语义决定。

禁止通过姓名字符串重新搜索实体。

必须使用真实 id。

实体已经死亡 / 转世 / 转界时，应进入现有历史或状态表达，而不是 JS 错误。

复杂度：S。

体验收益：极高。


## Q10 · 宗门名称、地点名称也尽量成为入口

同样检查：

- 宗门名
- 聚落
- Site
- 灵脉
- 战争双方
- 编年史中已有明确 id 的对象

如果系统已有对应 inspect / focus 能力，则允许点击。

原则：

只连接已经存在的能力。

不要为本任务新建“百科系统”。

复杂度：S。


## Q11 · Toast / 重大事件允许点击定位

对于已有：

- entityId
- sectId
- siteId
- x/y
- plane

的 Toast 或重大 Presentation Event：

允许点击提示，执行：

`focus → inspect`

如果只有坐标：

只定位。

如果什么定位信息都没有：

保持普通 Toast。

不要为了支持点击而修改模拟事件结构。

仅消费已有字段。

复杂度：S～M。


## Q12 · 检视面板补一个统一操作条

人物 / 宗门 / 地点检视顶部整理出一排非常小的上下文动作。

根据目标类型显示已有能力：

`定位`
`记挂 / 取消记挂`
`关系`
`宗门`

不存在的能力不显示。

不要让各面板自己复制一份业务逻辑。

复杂度：S。


## Q13 · 增加“最近检视”

只维护 UI runtime 状态：

最近 5 个被玩家主动检视的对象。

例如：

最近看过
沈禾
太虚门
断碑遗址
徐青

点击重新 inspect / focus。

限制：

- 不进入 World。
- 不进入正式 save。
- 换世界清空。
- 读档清空。
- 最多 5 条。
- 重复对象上浮。

这是非常便宜但非常好用的导航能力。

复杂度：S。

# 五、第三组：记挂系统补齐“我为什么记挂他”

现有记挂已经成立，不重做系统。


## Q14 · 记挂标题显示未读数量

BACKLOG #10 已指出目前只有整体红点。

本轮可以做一个很轻量的升级：

`记挂 · 3`

表示自上一次打开以来有 3 条与记挂对象相关的新变化。

不需要建设完整通知中心。

打开记挂区后：

未读计数归零。

已有红点机制可继续使用。

复杂度：S。


## Q15 · 记挂人物状态变化不能“突然消失”

检查：

- 死亡
- 飞升
- 进入幽冥
- 转世
- 夺舍
- 跨界

如果记挂对象已经不处于原人口数组：

UI 应尽量显示一个状态结果，例如：

`已飞升`
`已陨落`
`魂入幽冥`
`已转世`

而不是从列表无声消失。

优先读取现有历史 / watch / transfer 事实。

不要造第二套人物生命周期。

复杂度：M。

如果实现需要大幅修改模拟，跳过本项。


## Q16 · “记挂”动作本身增加明确反馈

成功：

`已记挂 · 沈禾`

取消：

`不再记挂 · 沈禾`

已经记挂时不要重复添加。

复杂度：XS。

## Q20 · 检查重要持续事件是否缺少结局

对应 BACKLOG #9。

只做审查和非常有限的补齐：

例如：

`某场战争结束`
`某持续灾祸消退`

要求：

- 不改变模拟。

如果某系统根本没有明确结束事实，不要为了本任务造一个。

复杂度：S～M。

# 七、第五组：存档安全感

这一组不是重构存档。

只改善玩家“敢不敢点这个按钮”。


## Q21 · 新世界 / 读档之前增加未保存保护

维护一个非常简单的 UI dirty flag。

发生以下玩家行为后标记 dirty：

- 世界继续推进过明显时间。
- 玩家执行干预。
- 玩家编辑地形。
- 其他会改变 World 的显式操作。

成功存档后清 dirty。

点击：

`重新开天`
`读档`
`导入`

如果 dirty：

弹出轻量确认：

`当前世界有尚未保存的变化，仍要继续？`

要求：

dirty flag 不是模拟字段，不进入 World。

不要做复杂 diff。

复杂度：S。


## Q22 · 存档操作统一成功 / 失败反馈

必须明确区分：

`已存入 槽3`
`已读取 槽3`
`已导出`
`存档失败 · 浏览器空间不足`
`导入失败 · 文件不是有效存档`

不要只写 console。

复杂度：XS。


## Q23 · 导入失败必须保证当前世界不被破坏

导入流程改成：

读取
→ parse
→ validation
→ 构造候选
→ 成功以后替换当前 World

任一阶段失败：

当前世界保持不变。

如果当前流程已经如此，只增加自动测试。

复杂度：S。


## Q24 · 存档槽增加轻量信息

不修改正式 save schema。

如果现有存档内容可以低成本读取：

槽位旁展示：

`槽3 · 仙历 482年`
或
`槽3 · seed 226 · 482年`

如果实现需要改 schema：

不要做。

不要为了显示信息复制整套 deserialize。

复杂度：S。


## Q25 · localStorage 容量预警

长卷存档已经接近浏览器 localStorage 上限。

利用现有序列化字符串长度，在保存前做粗略容量提示。

例如达到安全阈值时：

`此世界存档较大，建议导出文件长期保存`

发生 QuotaExceededError 时：

必须给用户明确反馈。

不要自动删除其他槽。

复杂度：XS。


## Q26 · 导出文件名变得有意义

如果当前还是固定文件名，改成类似：

`inkbox_seed226_day175200.json`

只使用安全字符。

不修改文件内容。

复杂度：XS。

`inkbox-ui-prefs-v1`

禁止保存：

- World
- selection
- RealmView Region
- gameplay state

如果担心 localStorage，本对象限制为很小的 JSON。

复杂度：S。


## Q30 · 增加“收起全部”

右栏增加一个轻量：

`收起`

一次折叠全部非核心区域。

不需要“复杂布局模式”。

复杂度：XS。

# 十、第八组：检视系统健壮性

## Q35 · 修复 BACKLOG #15：inspectAt 整数守卫

`inspectAt(x, y)` 不允许浮点坐标静默落到错误格。

- 或者非整数直接拒绝。

不得悄悄采用与地图不同的坐标定义。

- 转界
- 消失

显示：

或主动关闭旧面板。

复杂度：S。

凡间 / 上界 / 幽冥

时，在已有信息区显示一个短标签。

不要根据当前打开的 UI 窗口猜。

必须读取真实 picker / inspector plane。

# 十一、建议顺手加入的微型质量修补

以下都非常便宜，如果施工路径明确可以一起完成。

### Q38 · 防止双击导致重复命令

对明确 one-shot 的按钮避免快速双击产生重复执行。

不要给所有按钮加全局 debounce。

只处理有实际风险的命令。

### Q39 · DOM 按钮 busy 状态

导入、读档、构造新世界等存在异步步骤时：

短暂 disabled，避免重复点击。

### Q40 · 所有 destructive button 文案统一

例如：

`重新开天`

必须与普通按钮在文字和确认逻辑上区别明确。

不需要大红色视觉改版。

### Q41 · 滚轮只在地图区域控制缩放

如果鼠标正在右栏列表上滚动：

优先滚动面板。

不能同时让地图缩放。

如果当前已经正确，不修改。

### Q42 · 拖动与点击阈值统一

检查地图：

点击
拖拽
视界划选
相机平移

避免“只是手抖 3px 就被识别成另一种操作”。

已有 `VIEW_CLICK_PX = 6px` 时优先复用现有规范。

不要重新发明多个 magic number。

# 十四、模拟纯度门禁

虽然本轮主要是 UI，仍需执行一个非常重要的约束：

> 同种子、同玩家命令、同推进天数下，加入这些 UI 功能前后 World 与模拟 RNG 不应变化。

尤其注意：

- 最近检视不能进 World。
- panel collapse 不能进 World。
- tooltip 不能进 World。
- Toast 点击不能改变模拟。
- 视界关闭必须继续走既有 RealmViewState。
- UI prefs 不得进入 save。
- event 展示不得消费模拟 RNG。
- renderer 不得因为 UI 更新推动模拟。

除非本项任务本身属于已有合法显式 Command。

# 十六、完成判据

本轮不以“做了多少功能”为判断标准。

完成后应满足以下体验：

玩家按错东西时，游戏会告诉他为什么。

玩家不知道自己拿着什么工具时，界面会告诉他。

玩家看到一个有趣的人名时，可以点进去。

玩家看到一次重大事件时，可以找到发生地点或相关人物。

玩家记挂一个人以后，他不会毫无解释地从世界叙事里蒸发。

玩家翻几百年的史书时，新日志不会抢走他的阅读位置。

玩家准备毁掉当前世界时，游戏会提醒他还有没有保存。

玩家导入坏存档时，原世界不会跟着陪葬。

玩家打开一个两千人口的世界时，右栏不会变成长达几十屏的名单。

玩家忘记快捷键时，不需要重新翻 README。

玩家打开上界、幽冥、关系图、战争线、记挂、编年史以后，可以自然退回普通观察状态。

最终感觉应该是：

> 原本散落在游戏里的几十个功能，开始像同一个完整产品里的功能。

而不是再新增另一堆功能。
