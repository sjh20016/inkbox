## 一、这是什么

按《视觉参考说明文档 v0.2》与《M2-C 写意渲染基线》的约束，做了**三批**低模模块：
第一批是**建筑与地形岩体**（验证「凡间建筑母语言」是否成立），
第二批是**宗门宅院与废址遗存**（验证「修仙聚落的功能分化与时间痕迹」能否只用低模表达），
第三批是**特殊地形**（验证「贴地的地表场所」能否不靠体量、只靠**地面图案 + 少量立物**被认出）：

> **真 3D 低模空间 + 极低信息实体 + 像素约束表面 + 水墨统一。**

参考 `美术素材/范式素材参考/`（Kenney / KayKit）的**复杂度、模块化、比例与信息预算**，
**不复制其最终卡通审美**。中国建筑只取**识别符号**，不做建筑学还原：不堆瓦片、不做斗拱、不铺窗棂。

## 四、颜色词典（不是贴图）

`Inkbox_EntityAtlas.png` 是 **128×128 的 8×8 色格图集**，28 格有颜色，其余为纸色。
**它不是传统纹理，而是一张颜色词典**：每个几何面把 UV 钉在某个色格的正中心，NearestFilter 下取色精确。

全部资产**共享一张图集、一个材质**，这是批量实例化的前提。

颜色对齐 `src/inkbox/core/config.js` 的 `INK`，并吸收《中国画 AI 配色参考》：

| 层 | 色名 |
|---|---|
| 纸墨（骨架） | `paper` `paperDeep` `paperShade` `mist` / `ink` `inkMid` `inkLight` |
| 木石土 | `stone` `stoneDark` `wood` `woodDark` `clay` |
| 矿物点睛 | `cinnabar` `rouge` `gold` `azurite` `indigo` `malachite` `pineGreen` `orchid` |
| 三界身份 | `upperA/B/C/D` `nether` `netherMid` `soulFlame` `snow` |

**原则 E（颜色承担语义，不是装饰）**：大部分世界由纸白、墨灰、木褐、极淡水色构成；
较明显的朱、青、金只用于**宗门、功能建筑、特殊状态、灵气**等信息。

## 五、技术规格

| 项 | 值 |
|---|---|
| 格式 | **GLB**（glTF 2.0 binary，Three.js 直读）+ **OBJ/MTL** |
| 坐标 | Y 向上，基座 `y=0`，原点在底面中心 |
| 尺度 | 1 单位 ≈ 1 世界格 |

| 材质 | `pbrMetallicRoughness`，`metallic=0`，`roughness=1`，`doubleSided` |

| 索引 | **带索引**的图元（务必用 index buffer 绘制） |

## 六、接线方式

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

const gltf = await new GLTFLoader().loadAsync('美术素材/实验建筑资产/建筑/bld_house.glb');
const proto = gltf.scene.children[0];        // 单网格，材质已指向内嵌图集

// 批量摆放：共享同一 geometry + material，走 InstancedMesh，避免一实体一 draw call
const inst = new THREE.InstancedMesh(proto.geometry, proto.material, count);
```

**注意**：

1. 资产**自带朝向**（正面朝 −Z）。摆放时按需旋转即可。
2. 单件 GLB **内嵌**了一份图集（0.5 KB）。批量使用时，建议在游戏侧
   只保留**一个**共享材质，把各 GLB 的 geometry 取出复用，避免重复纹理对象。
3. `bld_wall` / `terr_rock` / `terr_terrace` / `terr_slab` 是**模块件**，可沿轴平铺。
   **特殊地形组里 `terr_spiritfield` / `terr_ancientroad` / `terr_blast` / `terr_battlefield` / `terr_array`
   都是 1.00×1.00 的整格地皮**，同样可无缝平铺成大片田垄 / 长路 / 焦土区。
   注意 `terr_plankwalk` 不是整格件（0.30×1.12），它是**线性件**，按走向摆放。
4. **特殊地形是「有朝向的地皮」，摆放前先看它把关键元件放在哪一面**：
   `terr_mountainpath` 的崖壁在 **−X**、`terr_lair` 的抓痕在 **+X**、`terr_immortalcave` 的洞门朝 **−Z**。
   标准 3/4 相机在 `(+X, −Z)`，把识别元件放到背面等于没做。
5. **本批资产尚未接入 Render3D**。接入属于 Art Pass 范围，需新的施工授权。

## 八、已知坑（踩过的，别重犯）

1. **Blender 是 Z 向上，glTF 是 Y 向上。** 几何模块用 Y 向上；进 Blender 时映射
   `(x, y, z) → (x, −z, y)`（绕 X 的纯旋转，det=+1，保持绕序与法线），导出时再由
   `export_yup=True` 转回。
2. **图集 V 轴两套约定。** 图集按 PIL 习惯生成（色格 0..7 在**顶行**）。
   - Blender 的 UV 原点在**左下** → 必须用 `UV_BLEND`（`v = 1 − v_gltf`）；
   - glTF/OBJ 的 UV 原点在**左上** → 用 `UV`。
   写错哪一边，结果都是「整块翻到纸色区 → 白模」。
3. **Three.js 的 `TextureLoader` 默认 `flipY = true`**，会把图集上下翻转。
   glTF 的 UV 原点在左上，所以自研解析器必须显式 `tex.flipY = false`
   （`GLTFLoader` 内部正是这么做的）。
4. **glTF 图元通常是带索引的**。忽略 index buffer 而直接按顶点顺序每 3 个凑一个三角形，
   会把网格退化成点云——症状是「几乎看不见 / 只看到一条细线」。
5. **Blender 在 `byteOffset` 为 0 时会省略该字段**。读取 `bufferView.byteOffset` 要写
   `(bv.byteOffset || 0)`，否则算出 `NaN` → 空 blob → 纹理加载失败。
6. **无头渲染用 Cycles，不要用 EEVEE。** EEVEE 需要 GPU 上下文，
   `--background` 下会丢纹理，渲染成白模。Cycles（CPU）稳定。
7. **OBJ 与 GLB 的 V 约定不同**：本批 OBJ 走 Blender 约定（`v=0` 在底），
   GLB 走 glTF 约定（`v=0` 在顶），两者均已验证一致，不要「顺手统一」。

### 造型可读性（第三批特殊地形踩出来的，是设计规律，不是 bug）

这一批十件里，**除仙人洞府、古阵遗址外全部返工过**（灵田 3 轮、栈桥 4 轮、妖兽巢穴 4 轮），
教训比技术坑更值钱。共同的病根是一句话：

> **低模下「像什么」由剪影与重复节律决定，不由你打算表达什么决定。**

#### A. 通用造型规律

1. **孤立一颗小方块永远读作「方块」。** 不读作灵气、不读作嫩苗、不读作骨。
   灵气要**细高柱**（灵泉）或**平铺辉斑**；嫩苗要**细而多**（灵田）；骨要**细长且散**（妖兽巢穴）。
   凡是想表达「一点什么」，都别用一颗方块。
2. **元件放在相机看不见的那一面等于白做。** 标准 3/4 相机在 `(+X, −Z)`：
   崖壁挡镜头（山道）、抓痕刻在背面（妖兽巢穴），都是白做。
   放关键元件前先问一句「这一面朝向谁」。
3. **长条形物件要沿 Z 铺展，不要沿 X。** 同一件 1.0 长的东西，
   沿 X 被 3/4 相机压到 **57%**，沿 Z 只压到 **82%** —— 沿 X 会让栈桥看起来像一张矮桌。
4. **接触表缩略图会让浅色资产「发白」。** 判断颜色与细节必须看**单体全分辨率图**（512×512），
   不要拿接触表下结论。

#### B. 「像建筑」是地形资产最大的陷阱

5. **别用项目的建筑母题去搭地形。** 本项目的建筑语言就是
   **方体 + 攒尖顶**（见 `bld_scripture` 藏经阁 = 三层递减 + 攒尖顶）。用它搭岩，
   试三次读成三个建筑：三块等大各带大金字塔 = **三间茅屋**；层叠递减的方块 = **藏经阁**；
   大方盒 + 单一大金字塔 = **亭 / 冢**（妖兽巢穴）。
6. **平顶方块必然是建筑。** 岩体要么用 `pyramid` 收顶（见 `terr_rock` 的岩语言），
   要么**非正交**：手工定义多面体，底边不等长不等角、顶点偏心、各面斜度互不相同
   （妖兽巢穴最终方案：六边形底 + 偏心顶点）。
7. **洞口做成规整矩形就是门 / 窗。** 野洞要**宽 > 高**，且口形不规则
   （用 2–3 块错深的暗色块叠出来）。
8. **家具与桥的分界在「横向连梁」。** 光溜溜的成排竖杆 + 平板 = 桌子；
   给每组竖杆加一道**横撑（排架）**，立刻变桥墩。桌子腿绝不会横着连梁（栈桥）。
9. **实心边墙会把长条件读成「托盘」。** 栏杆必须**透空**（细立柱 + 顶横杆），
   否则两侧连成一片实心，整件读成托盘 / 桌子（栈桥连中两次）。
10. **厚而高的池缘 / 田埂 = 托盘边框。** 灵泉初版池缘又高又厚又齐，读成**浴缸 / 泳池**；
    灵田初版田埂用**纸白**，土黄田面被一圈白框圈住，读成**托盘 / 画框**。
    边缘要**低、薄、不等高**，且**必须用土石色，不能用纸白**。

#### C. 图案要「连成面」，不要「摆成一排」

11. **密排到连成面才读作田，稀而高只读作棒。** 灵田初版 4 道粗垄彼此隔开，
    读成「托盘里摆了几根绿棒」；改成 **9 道宽垄 + 窄沟**（沟只有垄宽的 1/4）后立刻成田。
12. **同色同宽的道路接缝 + 车辙会拼成网格**，读作「铺砖地面」而非「路」。
    路的语法是**纵向铺面 + 深车辙 + 两侧留异色路肩**，横向接缝是敌人（古道）。
13. **等长的放射状元件会拼成「十」字**，读作符号而非爆炸。放射焦痕必须
    **长短不一 + 带偏角 + 夹杂碎块**（雷击地）。

#### D. 颜色也是造型

14. **同一个色号的两件东西会互相吃掉。** 灵泉初版水面与灵气柱**都用 `soulFlame`**，
    柱子在池里**直接隐形**。要让 A 突出，B 就必须退开：
    水改深青碧（`indigo` / `azurite`），柱保持亮色。
15. **浅色顶面会读成「搁板」。** 洞口岩檐顶面用浅色时，整块读成伸出来的一块板；
    改成与岩体同色后融回岩石（妖兽巢穴）。
