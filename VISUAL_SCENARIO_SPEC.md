# M2-C Visual Scenario Harness

`src/inkbox/render3d/art/VisualScenarios.js` is a debug-only module. `applyScenario(sandbox, name)` creates facts exclusively through the public seeded `newWorld` and `advanceDays` paths. It never inserts characters, villages, terrain or rifts. The three extensible recipe records are GOLDEN_A (small, 20260930, day 1440), TERRAIN_STRESS (medium, 20261003, day 10) and DENSITY_A (medium, 20260928, day 1800). Aging uses one `advanceDays(1)` call per day: a single large step is not equivalent. Names express intended coverage; each manifest identifies the actual generated POI, house count or entity.

`applyCamera(host, recipe, overrides)` resolves WORLD_OVERVIEW and REALM_BOUNDARY from world bounds and REGIONAL from the real height maximum. `applyVisibleCamera` resolves ENTITY_MEDIUM/CLOSE and SETTLEMENT from deterministic real cultivator-house candidates, favoring a 5–20-cell separation so a house does not bury the actor. It tries relative polar/yaw recipes and requires the first opaque hit among terrain, buildings, vegetation and all entity batches to be the selected entity. Five body projections supply a visibility ratio; at least three must reach that actor. The ordinary `r.pick` entity identity is recorded as a second check. SETTLEMENT additionally requires an in-frame, first-hit real house and tree. Elevation uses `ElevationField.at`. Numeric XYZ is diagnostic output, not the recipe. Missing coverage fails the run.

Run `node scripts/inkbox-render3d-m2c-browser.mjs --baseline` before product changes. Run `node scripts/inkbox-render3d-m2c-browser.mjs --after` after integration. Both use installed Microsoft Edge through zero-dependency CDP with GPU enabled and a 1500 × 940 DPR-1 viewport. Initial pre-change evidence remains in `reports/m2c/baseline`; official final screenshots/manifests/evidence go to `reports/release/render3d-m2c`, with `INKBOX_REPORT_DIR` as an optional override. Art profiles baseline, pigment (S1), ink (S1+S2), pilot are captured without changing camera/snapshot between them. The eight required filenames are ordinal+semantic names.

Each manifest records scenario, seed, preset/mapSize, worldDay, worldGenVersion, cameraRecipe/relative recipe/actual POI and resulting camera position, viewRealm, artProfile, viewport and source commit. Commit is the base revision; `renderSourceDigest` plus per-file hashes identify the actual dirty rendering source. Worldgen is tied to SHA256 source hashes of all three worldgen files. SHA256 of the entire JSON world (three realms, all typed arrays/facts) plus advanceState records the actual snapshot. Sandbox RNG resets to mulberry32(12345) before newWorld, including the greetOnBoot consumption; advanceState is fresh, and Life streams are reset by newWorld. The initial S0 set used day 10/day 60 and uncovered missing cultivator/house coverage. The release set keeps the eight final pilot PNGs and their manifests; baseline, pigment and ink comparison captures were trimmed after acceptance. Per-capture hashes remain in source-provenance.json, and the pilot images are the current visual samples.

Performance is CPU-visible `renderer.render()` submission timing after five warmup frames, with 60 samples, average/median/p95, calls, triangles and visible aggregate instances. It is not GPU timer-query timing or a frame-rate guarantee.

The 600-frame lifecycle check rotates one full revolution, zooms 1.45–18, resizes/restores the viewport, opens/closes upper/nether windows, toggles all profiles and samples submitted GPU resources after warmup and at the end. Dense picking checks visible-plane agreement. This is a bounded stability run (roughly ten seconds at 60 Hz), not a long-run endurance claim. Separate root-owned soak evidence covers a longer run.

S0.5 `probeRenderTargets` temporarily uses the existing WebGLRenderer: linear-color RT with DepthTexture/MSAA4 → fullscreen triangle → color-managed screen. It checks full/half resolution at DPR 1/1.5, framebuffer completeness, depth sampling by readback, explicit RT resize, errors and resource disposal. It restores renderer state in `finally`; it never becomes the product default. The technical gate requires all allocation, depth and resize checks to pass; a pass alone does not justify a default S3 performance claim.
