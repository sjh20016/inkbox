## 一、这是什么游戏（30 秒版）

《坐天观井》是一款**水墨画风的修仙世界盒子（World Box）沙盒**。

- **玩家是谁**：失忆的**天道 / 观井者**，坐在「井外」看「井中」的水墨山河与芸芸众生。
  游戏名是「坐井观天」的反写，众生坐井观天，天道坐天观井。
- **玩家做什么**：以神格笔刷抬山、放水、降灾（`powers.js`），以「仙道九式」点化凡人、
  引灵脉、降天劫、传功法、点化飞升、立宗门（`divine.js`）；也可以**什么都不做，只看**。
- **世界自己会跑**：凡人生老病死、觉醒灵根、拜师结侣、开宗立派、宗门大战、转世夺舍；
  修士有灵根（五行 + 变异）、境界（炼气→…→合体，上界另有大乘）、十二道途（九正三邪）、
  天劫异象、心魔、道心试炼、因果业报。
- **三界现状**：上界（紫霄）、幽冥界（冥河）与空间裂缝的最低生态 / 跨界机制已交付；06 册中的【预留】表示该条文案未承诺接线，不表示整个三界系统尚未实现。三界规则看 THREE_REALMS，阶段看 ROADMAP。

**活跃源码与历史来源（务必分清）**：

| 分支 | 入口 | 状态 | 文案位置 |
|---|---|---|---|
| 原版 V4（卜算子羁绊、命线、多 UI） | 旧版本的 `index.html` + `src/` | Git 历史考古来源，源码不在当前工作树；当前 index / game 是 Inkbox 跳转页 | 旧版本 `src/data/*.js`、`src/content/busanzi/*.js` |
| **水墨沙盒（世界盒子迁移版，活跃开发）** | `inkbox.html` + `src/inkbox/` | 活跃，文案接这里 | `src/inkbox/core/lore.js`（词池与文案池）、`src/inkbox/sim/*.js`（内联文案） |

本套素材**默认服务于水墨沙盒（inkbox）**；为原版扩写时，沿用原版的 `{text, weight, condition}` 结构。

## 二、剧情灵魂：这个游戏靠什么打动人

真正打动人的是下面这六件事，境界数值、宗门胜负都在其次。所有文案都要为它们服务，不能稀释它们。

1. **看见 ≠ 知道；注视本身有重量。** 玩家是旁观者，不是操盘手。文案要反复让玩家感到：
   你看见了一个人的一生，而他永远不知道你在看。这份「只有你记得」的重量，就是天道的滋味。
2. **命线、因果、账本。** 「名字是世界保存因果的方式」。命名、立碑、传记、史册，都是世界在记账。
   文案要爱写「账」「名字」「记得 / 忘掉」。
3. **物比人久。** 人活几十年，法宝、洞府、残页、半枚铜钱、一座山名能活几百年。
   让物出场、让物换主、让物记得人，是本游戏最独特的苍凉感（法宝系统专门承担这一点）。
4. **天道也会看走眼。** 玩家不是全知全能的神，卜算子也会算错卦。看错不丢人，看错还嘴硬才丢人。
5. **市井消解宏大。** 再大的飞升、大战、天劫，也要从卖瓜子的、赶集的、挑水的、补锅的眼里过一遍。
   宏大被生计一照，才有了人味。这是「世界盒子」视角的天然趣味：**神在看人间，人间在忙饭点**。
5. **留白与克制。** 大事写小，后事不表。「天光收回云里，像什么都没发生过」「后来的人只当是地势如此」。
   不喊口号、不替角色抒情、不把话说满。
6. **井与井口。** 飞升是「去井口看看外面」；卜算子在井外守了一千年；上界是另一层井。
   「一层看一层，谁也别笑谁」是三界篇的魂。

> 一句话总结声音：**用说书人的嘴、史官的笔、守灯人的心意，写一群不知道自己被看着的人。**

## 三、三层叙事声音（最重要的一节，不许串味）

游戏里有三个「说话的人」，各有严格的语言区。**90% 的文案事故都是声音串味。**

### 声音一：卜算子（对玩家说话）

- **他是谁**：离卦之灵（标记 ☲），天道引路人、井外唯一肯等玩家醒来的人；算命的、卖消息的、
  说书的、必要时往玩家脑门上拍巴掌的。
- **口吻**：**半文半白 + 市井痞气**。自称「小爷我」，感叹「我的天」（双关：他面前的就是天）；
  常用「嗐、啧、喏、嗨、哈哈哈」；称修士「她/他/那孩子/小蚂蚁」，称世界「井里/这摊墨」。
- **他的三条铁律**：① 不剧透（可说「线抖了」，不可说结局）；② 不代玩（不指挥点哪里）；
  ③ 不背锅（天劫生死是众生自己攒的，反复声明）。
- **他的温度**：嘴损，心软。会编假古话自嘲（「古人云……没听过？那就对了，小爷我方才编的」）；
  对玩家过度干预会沉脸规劝（「愈合是世界自己长回去，雕刻是你一刀一刀刻出来」）。
- **只在这些地方说话**：引导、注视 / 落子反馈、里程碑、加载页、空状态、二次确认的副句、彩蛋。
- **不许**：出现在编年史正文、墓志、碑刻、功法残页里（那些是井里的人写的，他不在井里）。
- 素材见 **01 册**；现有代码：`lore.js` 的 `BUSANZI`、`sim/busanzi.js`、原版 `src/content/busanzi/`。

### 声音二：史笔（编年史 / 系统反馈）

- **它是谁**：世界自己长出的那支笔，是后世修史人、茶摊说书口、碑刻残字的混合体，无人称、无口癖。
- **口吻**：**白描、克制、短句、留白**；人名一律加 `【】`；黑色幽默藏在细节里，不跳出来逗笑。
- **两个亚型**：
  - **正史体**：「是岁大疫，死者无算。」字越少事越大。
  - **市井体**：「围观人群自觉退开三十丈，卖瓜子的挤到了最前排。」（用于大战、丹会、渡劫等热闹场面）
- **不许**：用「小爷我」「我的天」；不许出现玩家、系统、随机、概率、数值；不许替死者喊冤抒情。
- 素材见 **02 册**；现有代码：`lore.js` 的 `NARRATIVE`、`war.js` / `worldEvents.js` / `powers.js` 的 `world.record()`。

### 声音三：世界内文本（井里的人写给井里的人）

- **它是谁**：具体的、有名有姓（或佚名）的世界内作者：开山祖师、炼丹前人、稳婆的儿孙、
  茶摊说书人、刻碑的石匠、写信的修士、唱童谣的孩子。
- **口吻**：**古雅、多义、允许残缺**（「□□」「（下缺）」）；作者必须在场，想象得出谁写的、写在什么上。
- **品类**：宗门楹联门规、功法残页、偈语箴言、碑刻、书信、挽联、符箓法宝铭文、坊市招牌、童谣谶语。
- **不许**：出现「天道/玩家/系统」等穿帮词（可以写「天」「命」，那是他们信的天，不是屏幕外的你）；
  童谣只许影射**已发生**的事，禁止预言未来。
- 素材见 **04 册**（凡间）、**06 册第七章**（三界）。

### 另有两个「半声音」

- **墓志 / 传记（03 册）**：后人执笔者，克制到近乎冷酷，但允许偶尔一笔见血；
  墓志是硬约束文体（≤40 字）。「观井者曰」是**玩家本人**在史册里的史评署名，不是卜算子。
- **界面文字（05 册）**：按钮 / 数值反馈用中性文言，不耍贫嘴；只有加载页、里程碑、空状态、
  确认框副句可用卜算子声口。**误事的地方不搞笑。**

### 声音速查表

| 你要写的东西 | 用谁的声音 | 自称 / 标志 | 典型长度 |
|---|---|---|---|
| 新手引导、注视反馈、里程碑、加载句 | 卜算子 | 小爷我 / 我的天 / ☲ | 15–60 字 |
| 天灾、突破、生死、大战、宗门、法宝记录 | 史笔（正/市井） | 无人称，【人名】 | 20–55 字 |
| 墓志 | 后人 | 无 | **≤40 字** |
| 传记正文 | 后世史官 | 「观井者曰」仅卷尾 | 按八段结构 |
| 楹联、残页、偈语、碑、信、童谣、招牌 | 世界内具体作者 | 落款 / 佚名 | 一首 / 一封 / 一句 |
| 按钮、报错、数值 toast | 中性文言 | 无口癖 | ≤16 字 |

## 五、怎么接线（技术规范）

### 5.1 文案池的数据结构

**水墨沙盒（inkbox）**用的是极简结构。`core/lore.js` 里：

```js
// 编年史池：字符串数组 + 占位符
export const NARRATIVE = Object.freeze({
  breakthrough: [
    '【{name}】突破至{realm}，周身灵气如潮汐翻涌，方圆百里的修士皆感应到这一变。',
    // …新增条目直接往数组里加
  ],
});

// 取值：一次 rng()，等概率
export function narrate(rng, key, params) {
  const pool = NARRATIVE[key];
  if (!pool || !pool.length) return '';
  return fillTemplate(pickFrom(rng, pool), params);
}
```

**需要权重时**，学 `sim/possession.js:194-207` 的写法：

```js
const POOL = Object.freeze([
  { text: '……{name}……', weight: 1.0 },
  { text: '……', weight: 0.9 },
]);
// 一次 rng() 加权抽取（possession.js 的 pickText 可直接参考）
```

**原版主线（src/，已冻结，仅供参考）**用 `{ text, weight, condition: (ctx)=>true }`，
`condition` 是上下文过滤函数；为原版补文案时才用这个结构。

### 5.2 占位符规范（统一约定）

- 形式：`{key}`，花括号、小驼峰 / 单词。渲染走 `fillTemplate`（`lore.js:508`）：
  **变量缺失时保留 `{key}` 原样，绝不置空、绝不报错吞掉**，所以接线时必须传齐参数，
  渲染后要肉眼检查有没有漏网的花括号。
- 人名在编年史 / 史笔中一律 `【{name}】`；在卜算子台词里可直接 `{name}` 或「她/他」。
- **占位符总表**（跨六册，新增请先登记在此）：

| 占位符 | 含义 | 占位符 | 含义 |
|---|---|---|---|
| `{name}` | 人名（主当事人） | `{place}` | 地名（placeName 生成） |
| `{a}` `{b}` | 大战 / 关系双方（宗门或人） | `{sect}` | 宗门名 |
| `{realm}` | 境界称谓（realmLabel） | `{root}` | 灵根名 |
| `{killer}` | 击杀者 | `{cause}` | 死因短语 |
| `{omen}` `{omenNote}` | 天劫异象名 / 解释 | `{outcome}` | 突破失败后果 |
| `{form}` `{formNote}` | 心魔形相 / 说明 | `{question}` `{result}` | 道心试炼问 / 结果 |
| `{artifact}` | 法宝名 | `{heir}` | 传承者 |

| `{disaster}` `{note}` | 危机名 / 说明 | `{village}` | 村名 |

### 5.3 句末标点与长度

- 编年史 / 史笔条目**一个句末标点收尾**（句号为主，不用感叹号、不用 emoji）。
  代码有 `endSentence()`（`biography.js:287` 一带）兜底，但池内要自律，别依赖兜底。
- 长度红线：编年史单行 20–55 字（市井长句 ≤70）；墓志 **≤40 字**（`EPITAPH_CAP`，超了会被截断成半句）；
  加载句 ≤24 字；tooltip ≤16 字；按钮 ≤6 字；卜算子台词 ≤60 字（羁绊场景 ≤100）。
- 卜算子台词里**唯一允许的符号**是 ☲（他的卦印），其余 emoji 一律不许进任何文案。

### 5.4 随机性铁律（本项目最容易闯的祸，务必读懂）

1. **主随机流 `Life.rng` 是全世界共用的一条种子流**，世界生成、繁衍、觉醒、抽签全走它。
   **在文案池里多调一次 `rng()`，就会改变后续所有抽签，几百年后的世界整个漂移**，
   既有长测标定（如「800 年飞升 33 位」）全部作废。
2. 因此：**扩池 = 只往数组里加字符串，绝不新增 `rng()` 调用次数、不改抽取顺序**。
   池子从 3 条变 30 条，每次仍然只抽一次，安全；把「先抽大类再抽小类」改成两次抽签，出事。
3. 新系统若确需独立随机性（如未来的裂缝 `riftRng`、上界 `upperRng`、战争 `warRng`），
   必须用 `mulberry32(seed ^ 魔数)` 开**独立随机流**，并写进存档 / 照 seed 重建策略。
   这是工程决策，不是文案决策，文案 AI 不要自行发明。
4. 文案模块（纯字符串 / 纯模板）**本身不允许抽任何签**。

### 5.5 「字段存在 ≠ 字段生效」与「不替系统造记忆」

- 这个项目反复出现一种病：字段写了、函数返回干净、测试全绿，但没有任何读者，功能等于不存在。
  **文案不许描写系统里不存在的机制**。例如：
  - 幽冥灵根的注释承诺「死后易成鬼修」，但机制不存在 → 不许写「幽冥灵根者死后化鬼修」的编年史。
  - 上界、裂缝、幽冥地图未实装 → 06 册全部封存，UI 上一个字都不许提前露。
- **凡人传记事件句（03 册第三章）尤其危险**：只能由真实数据（婚侣、子女、聚落、灾年、生卒地）
  推导，没有数据支撑的「他三岁丧父」不许生成。宁可留空卷（D18 系列），不许编一生。
- 数字必须来自真实账本（`warLog` / `deadLog` / `riftLog` / `popLog`），
  不许为了文案好看虚构「死伤三千」，单条事件会被裁剪，累计数一律读 `xxxLog`。
- **注意区分两种数字**：上面禁的是**机制统计数**（总人口、总死伤、总飞升这类会被玩家与面板核对的数）；
  而「多了十七座新坟」「备下四十斤粉」「拾到无主飞剑七柄」这类**白描修辞数**（笔记体以具体小数增市井真实感，
  现有 `war.js` 的「三十丈」「二两瓜子」同例）**允许且鼓励**，它们不冒充系统统计，无需接账本。
  判断标准：这个数若进了面板 / 总览，就必须真实；只活在一句史笔白描里，就是修辞。

### 5.6 不新造中文词（命名纪律）

- 境界只用七阶：炼气 / 筑基 / 金丹 / 元婴 / 化神 / 合体 / 大乘（大乘仅上界）。
  剑仙·丹仙·阵仙·符仙·散仙是仙使类型或尊称，不是等级。
- 人名、村名、宗门名、灵根、道途、功法、法宝、秘境、灵兽、宗旨、堂号、道号、姓氏
  **一律走 `core/lore.js` 既有词池与生成函数**（`generateName` / `generateSectName` /
  `generateVillageName` / `generateDaoTitle` 等），不要在文案里硬造新的专名。
- 例外：**世界内文本**（04 册的诗联偈语碑信、06 册的仙门楹联）是原创文学内容，允许自由书写；
  但其中若需要嵌入专名，仍用占位符，由系统填充。
- 鬼修六级（游魂/怨灵/厉鬼/鬼将/鬼王/鬼帝）、魂分五路（自然转世/滞留/鬼修/怨魂化/魂火散尽）、
  幽冥三物（轮回莲/聚阴符/驱鬼符）是考古定名，不得擅改或另造同义词。

## 六、文风指南（怎么写出对的味道）

### 6.1 卜算子仿写自检（写完念出声）

1. 有没有「小爷我 / 我的天 / 嗐 / 啧 / 喏」这类市井气？没有就太端着了。
2. 他是不是在**剧透 / 指挥 / 邀功 / 背锅**？占一样就重写。
3. 他的温柔是不是藏在损话后面？直白煽情 = 失败（参考「伞旧了，补补还能遮你那边」）。
4. 把「小爷我」三个字删掉，这句话还成不成立？成立才说明内容本身有用，不是靠口癖撑着。
5. 他会不会对**同一个世界事件反复说同一句话**？同组至少 3 条以上再接线。

**正例**：
> 又走一个。井口就那么大，谁都想去看看外面。
> （有母题「井口」、有留白、不评价玩家对错）

**反例**：
> 恭喜玩家！您成功点化了一名修士飞升，获得功德+100！
> （系统腔、游戏腔、数值穿帮、把天道当玩家打工，四重事故）

### 6.2 史笔仿写四把尺子

1. **能不能拍成一个镜头？** 写动作和物象，不写心情形容词。
   正：「血渗进土里，来年那里草长得格外好。」 反：「他死得十分悲惨，众人非常伤心。」
2. **有没有一个「小人物的眼睛」？** 大战写卖瓜子的，飞升写聋子李四，丹会写屠户家的狗。
3. **敢不敢少写后半句？** 「两人谁也没提下次。」后事不表，余味才长。
4. **物在不在场？** 每写三件大事，至少有一件让物（剑、锅、碑、鞋、钥匙）比人先被记住。

### 6.3 墓志写法

- 一问：**这个人一生最重的是哪一件事？** 只写那件。善战写最后一战，铸器写他的器，母亲写她等的人。
- 二砍：砍到 40 字以内还能站住。砍不掉的字，才是字。
- 三忌：忌履历表（「历任××、精研××」）、忌谀辞（「伟大的」「不朽的」）、忌标点感叹号。

### 6.4 世界内文本写法

- 先回答：**谁写的？写在什么上？为什么写？谁会读到？** 答不上来就别动笔。
- 残页要敢残，碑刻要敢替人隐讳，书信要有家务事（「娘的咳疾莫再拖」比「道心坚定」动人十倍）。
- 童谣要像孩子唱的：顺口、不讲理、大人听不懂但心里一咯噔。

### 6.5 通用禁区清单

- ❌ 现代网络梗、流行语、广告腔、游戏系统腔（「获得」「解锁成就」「+100」「NPC」「刷新」）。
- ❌ emoji（卜算子的 ☲ 除外）、颜文字、火星文。
- ❌ 真实存在的宗教 / 政治人物与影射；本游戏虽为架空修仙，亦不碰现实敏感。
- ❌ 色情低俗、为血腥而血腥；死亡写冷、写重，不写猎奇。
- ❌ 让卜算子出现在井内文本里，或让史笔开口叫「玩家」。
- ❌ 预言具体未来事件（卜算子不剧透，童谣只影射已发生之事）。
- ❌ 标点一逗到底 / 满篇感叹号 / 句末漏句号。
- ✅ 可以有黑色幽默、可以有市井狡黠、可以让邪修像个人、让正道有私心，世界是灰的，墨也是。

### 6.6 去 AI 味清单（本项目适用版）

> 来源：开源规则集 `lieflat-less-ai-tone`（https://github.com/larashero3-dotcom/lieflat-less-ai-tone ）。
> 该项目用 629 篇人机对照语料检验 26 项候选「AI 文风」，只有 11 项通过统计检验。
> 以下按本素材库的仿古 / 半文半白语境改写，**只列统计上成立的，宁漏勿滥**。
> 三条总原则：**白名单制**（只改下面列出的，没列的不许「顺手优化」）；**信息守恒**（改写不删事实、不增事实，只换语序和标点）；**不做语义层改写**（不许借润色之名重写别人的句子）。

**一、破折号（本库曾是头号问题，务必克制）**

- 统计上 AI 用破折号是人类的约 3 倍。最典型的 AI 腔是「白描一句——补一句点评 / 揭晓」。
- 史笔、墓志、碑刻、残页、书信、加载世界观句里**基本不用现代破折号**，改用逗号、句号、冒号（总说分说时）。
- 卜算子是口语体，破折号只留给三种真实口语功能：**话头被自己打断**（「至于我——问了也是白问」）、**语气词前的拖腔**（「答案嘛——嗨」）、**嘴硬转折 / 自我打补丁**。一段至多一个，能换逗号就换。
- 豁免不改：落款（「——卜算子 字」「——云边客 {name}」）、话语中断（遗言「剑——替我还给师父」）、史传副题体例（「——据某某辑成」）、话本里抖包袱的刻意停顿。

**二、翻案腔（「不是 A，是 B」）**

- 「不是……而是 / 并非 / 与其说……不如说 / 看似……实则 / 你以为……其实 / 说到底 / A 不重要，重要的是 B」这类「先树一个读者并没有的误解、再一把推翻」的句式，是 AI 评论腔的指纹。
- 改法：**直接从正面下判断**。「最动人的不是法宝，是墙上几行字」→「墙上那几行字，比法宝还动人」。
- 豁免：① 行文确实用材料走过「误解→看清」的过程（如乡人先把裂缝当天门、修士后认清是伤口）；② 卜算子当面对玩家做口语自我纠正（「我先前看错了，那不是死兆，是离兆」）；③ 偈语、注疏、前人眉批里的「非 A 乃 B」是禅宗道家典籍的原生句式（「刍狗不是骂你，是说天地不偏心」），属于文体传统，保留。

**三、顿号罗列过密**

- 一个分句里两个以上顿号、并列三项以上时，要么概括，要么拆散、让其中一项换句法。
- 豁免：真清单（招牌名池、符药名目、法条式门规）、临终三事这类「清单本身就是情感」的句子、引用典故原文（如寒山拾得「谤我、欺我、辱我……」一字不动）。

**四、相邻句同构**

- 连续两句以上同一个骨架（「他……。他……。他……。」），打散，换主语、换长短。
- 豁免：文学性的刻意排比与层递（「山不动，水在动；水不动，人在动」）。

**五、冒号与提示语空转**

- 「核心是：」「关键在于：」这类提示语 + 冒号、以及一句话空转半天才引出列表，删掉提示语或改句号。
- 豁免：说话引语、小标题、列表内、真正的总说分说（「三件俗事：肉钱、燕子窝、小女儿」）。

**六、序数词当小标题**

- 通篇「第一、第二、第三」做小标题是说明书腔；叙事文本里少用。
- 豁免：步骤性编号且后文靠「第三步」回指的（工作流、门规条数）。

**七、理想化职业人格喻体**

- 「像一位智慧的长者」「像永不疲倦的守护者」这类空洞职业人格比喻，改成具体的人或具体物象。
- 本库的方向是「像个守了四十年茶摊的老板娘」这种**具体人**喻体；比喻本身人类用得更多，不禁比喻，禁的是只有职业、没有人味的比喻。

**八、概括词盖掉具体数字**

- 手里有具体数，就不许用「大幅 / 显著 / 无数」盖过去；「十七座新坟」「四十斤粉」「房价翻了五倍」永远比「死伤惨重」好。
- 反过来，账本里没有的数字一个都不许编（见 5.5）。

**九、起手式**

- 「说白了」「说穿了」「总而言之」「先说结论」开头，删。卜算子口语另有自己的起手（「喏」「啧」「你猜怎么着」），也不可每段都用。

**十、翻译腔五种**

- 过长前置定语（「一个充满了灵气与机遇的世界」）；「当……时」前置从句；「对于……来说」话题壳；句首路标「然而 / 因此 / 此外」；「这意味着……」复述句。仿古文本天然免疫，写现代体的说明文档时自查。

**十一、段首零主语评论**

- 「值得注意的是」「看起来」开头且没有回指词，补主语或补「这」。

**明确不许改的（统计上人类反而用得更多）**：设问（人类用设问约为 AI 的十几倍，卜算子尤其该多问）、比喻、句内同构排比、单字虚词、被动句 / 名词化 / 长句、句长段长的参差。**不要为了「去 AI 味」把句子改得长短划一、把文气改平。**

**文体豁免总纲**：对话体（卜算子）、小说散文、偈语注疏、童谣碑文按各自文体的真实传统判断；规则与第三章「声音」、第六章各文体写法冲突时，以声音和文体为准。改完后，新增条目请自查：破折号是否又写成了「白描——点评」？是否又写了「不是 A，是 B」？

## 七、扩写与接线工作流（给 AI 的标准作业程序）

接到「加文案」的任务时，按顺序做：

1. **定位事件**：这条文案在哪个系统触发？读对应 `src/inkbox/sim/*.js` 的函数与现有 `world.record()` 调用，
   搞清楚触发条件、频率、能拿到哪些实体字段。**没读代码不写文案。**
2. **定声音、定册子**：查第三章速查表与第四章索引，确定用哪个声音、进哪一册、哪一组。
3. **定占位符**：从 5.2 总表里挑系统**真的能提供**的字段；提供不了的字段不许写进句子。
4. **写足池子**：同组一次性写 3–8 条（高频事件 6 条以上），保证长测不复读；
   每条过一遍第六章的自检尺子与长度红线。
5. **标注与登记**：在素材册里按编号登记；新占位符、新事件组同步登记到 00 册。
6. **接线**：只往池数组里加字符串 / `{text,weight}`，**不动 rng 调用次数与顺序**；
   传齐 params；需要新 kind（编年史分组键）时用自由字符串并在接线 PR 说明。
7. **验证**（缺一不可）：
   - 全局搜渲染后文本，确认没有残留 `{key}`、没有英文草稿词、没有超长句；
   - 墓志类跑长度断言（替换占位符后 ≤40）；
   - 跑 `scripts/inkbox-smoke.mjs` 与 `inkbox-longrun.mjs`，确认世界线读数无异常变化
     （飞升数、转世数、人口曲线等基线不被文案改动影响，**纯文案改动不应改变任何模拟读数**）；
   - 实跑 / 截图看编年史面板、人物面板、UI 是否换行炸版；
   - 预留内容确认在当前版本**完全不可见**。
8. **交付说明**：注明新增了哪些池、各多少条、接到了哪个文件的哪个键、跑了哪些验证。

### 「我想加一个现在没有的文案触发点」

- 先判断：是**纯文案缺口**（事件已存在，只是没话说）→ 直接扩池。
- 还是**机制缺口**（想要的事件系统里不存在，如「幽冥灵根化鬼修」）→ **停止**，
  这属于设计 / 工程任务，去读 `INKBOX.md` 与 `reports/design/`、`reports/migration/`，
  走设计流程，文案只能随机制一起做，不能先用文案假装机制存在。

## 八、关键事实速查（写文案时随时回来核对）

- **纪年**：仙历，一年 360 日（`TIME.daysPerYear`）；节奏：30 日一道途觉醒判定、30 日领土重算、
  宗门自然立派每 20 年看一次；仙使 150–250 年一至、丹会 30–50 年、秘境 80–150 年、洞府 60–120 年、
  世界危机第 45 年起。
- **境界寿元（年）**：炼气 110 / 筑基 240 / 金丹 620 / 元婴 1500 / 化神 3600 / 合体 7600 /
  大乘 16000（上界，待标定）。凡间修为上限 60 级（合体大圆满），即飞升门槛。
- **灵根**：金/木/水/火/土，单灵根至优、五行杂灵根至劣；变异灵根：
  天雷、寒冰、罡风、烈焰（rare），阴阳、时空、混沌、鸿蒙（legendary）；另有幽冥灵根（鬼修承诺尚未实装）。
- **十二道途**：剑/体/丹/符/阵/器/音/佛/灵 九正，血/尸/魂 三邪。

- **道心五问**：你为何修道 / 何为道 / 道与情孰重 / 长生是否值得 / 力量的意义。
- **失败三档**：境界倒退 / 跌落本阶 / 走火入魔（疯 30 游戏秒）。

- **宗门**：五行词池命名（金·剑峰、木·药谷、水·江阁、火·丹鼎、土·山岳），十大宗旨
  （避世清修/斩妖除魔/丹鼎济世/夺脉争锋/万法归宗/以杀证道/符箓通神/阵法守御/灵兽共生/商贾积财）。

  四种危机（赤地旱岁/饥岁围城/妖潮压城/地脉覆城）、八部灵兽（青鸾/白虎/玄龟/火凤/九尾狐/麒麟幼兽/应龙/白泽）、
  七部禁术（噬血魔功/万魂幡/天魔解体/炼尸大法/搜魂术/血祭大阵/化魂大法）。
- **法宝**：品阶 凡品→灵品→宝品→仙品→极品→圣品→仙品遗刻（特殊）；
  有铸造/获得/传承/遗失/损毁/器灵初生/锈蚀成泥完整生命周期，是「物比人久」的主载体。
- **夺舍**：境界 ≥20、元神不散 15%、找更低境界容器；成功后名带「·异」；亲友会起疑（饭桌、镜子、旧伤、扁担门槛）。
- **转世**：死后按污染/业力等分流；高境界魂继承灵根、灵根提品；宿慧分「记忆碎片/宿缘/灵根继承」；
  魂池上限 120，到期按「最早到期」取魂（此排序是血泪教训，不许动）。
- **上界（预留）**：开局十二人三始祖线；无凡人；仙城借 `villages` 容器；战争当人口阀；
  裂缝是开视界的副作用，开在划选边缘，一生漏几件东西；凡人被吸=「失踪」+上界《在途簿》可查。
- **幽冥（预留）**：幽墨冥河图，一条横冥河；鬼修六级；魂分五路；三物轮回莲/聚阴符/驱鬼符；
  阳世天火/绝灵地/洞天会影响幽冥怨魂压力。
- **玩家侧规模感**：中堂世界 288×180 格；开局约 160 人、自然长到约 1400 人；
  800 年实测飞升约 33 位、约 200 座宗门（大部分活不过百年）。写「盛世」「人烟」时以此为度。

## 九、版本与维护

- 素材版本：v1.0（随 inkbox 活跃分支维护）。
- 机制改动后（尤其上界 / 裂缝 / 幽冥实装、境界表扩充、随机流调整），**对应册的【预留】条目要逐条解封或改写**，
