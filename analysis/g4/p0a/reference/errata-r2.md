# 勘误与修订说明（R2）

> **结论**：五条审查意见全部成立，R2 已逐条处理。主路线不变（静海定界仍是唯一近期主线），但定性从“海洋 RULE_CHANGE + 内陆 EQUIVALENT”收紧为“整体 RULE_CHANGE，只有远岸内陆事件的陆地水量逐格一致”。浏览器 / GPU 收益仍是未测假说，由 G4-P0-A 判定。

## 问题一：R1 并未实现“固定海平面” · 成立
- 原型 `stepWaterR1` / `stepErosionLand` 只是跳过海格：海面偏差被冻结（长测中海格 water 与 `SEA_LEVEL − height` 的最大误差恒为 2.4e-3）；泥沙可以沉积进海格；发生陆地侵蚀后调用的原版 `stepThermal` 是全图热力，会改海床；海上注水 / 抽水没有边界归一化。
- R1 长测“零漂移”的真正原因是那张图的陆地上根本没有水（`riverBase` 为 0），陆地侵蚀从未触发，缺陷没有被走到。
- **修复**：原型更名为 `V2_seaSkipProto`（只用于复现旧数据）；新增 `V3_staticSeaStrict`：每步把海格归一化为 `SEA_LEVEL − height`；泥沙落到海格即消失；热力只在陆地格之间、侵蚀 bbox ±3 内运行；进入时一次性归一化（标准图 69,751 格）。
- **新证据**：V3 在 3000 步内海格误差恒为 0、海床改变 0 格（两张图）；海上注水 / 抽水 / 洪水 / 抬高海床之后，偏离边界的 88 / 88 / 172 / 47 格在下一个水文步全部归零。
- **结论改写**：原型证明了“停止常态海洋更新可以大幅降本”；V3 证明了“静海边界不变量可以在 Node 中保持”；两者都没有证明“静海规则在玩法上正确”。玩法正确性要靠场景验收与产品确认。

## 问题二：洪水等价只测了一个场景，且是汇总值 · 成立
- **修复**：新增 `oracle.mjs`：6 个场景 × 2 张图 × 400 步，对 water / height / type / qi 逐格精确比较（不四舍五入），分内陆带（距海 ＞ 4）和沿海带。
- **结果**：
  - 远岸内陆洪水、雕刻 + 降雨、海上编辑：内陆带 water **逐格 0 差异**（两张图）；群岛图四层全部 0 差异。
  - 标准图内陆有 30 格 height 不同（max 8.2e-4，type / qi 1 格），与场景无关：现状每步都因海床侵蚀触发**全图**热力，V3 去掉了这一点。这也是规则变化。
  - 沿海洪水（距海 3）：**不等价**。第 100 步陆地湿格 V0 为 106、V3 为 0；内陆带 92 格 water 不同。机制：现状注入海格的水会抬高局部海面并回灌岸边，V3 的海是固定水位的无限容量边界。
  - 沟渠通海：**不等价**（内陆 84 格 water、103 格 height 不同）。
  - 大坝：**场景无效**。构造的坝没有蓄住水（第 50 步已干，早于第 60 步的溃坝），所以大坝 / 溃决仍未验证。
- **结论改写**：只能说“距海 ＞ 20 格的已测内陆事件，陆地水量逐格一致”；沿海和通海是规则变化，需要产品确认；大坝待测。

## 问题三：Node 下游不能代表 main 的真实 GPU 收益 · 成立
- 核对 blob：`hydrology.js`、`powers.js` 在 main 与 H3 一致；`PlaneStage.js`、`WorldRenderBridge.js`、`TerrainMesh.js` 不一致；`terrain.js` 不一致，但只差在 `decayOverlay`，与水文无关。
- **修复**：`downstream.mjs` 改为从 `INKBOX_ROOT`（main `e1e5503`）导入 PlaneStage / ArtPass；每次输出记录 rev 与 blob 前缀。R1 中基于 H3 PlaneStage 的下游表作废。
- **新数据**（main，同批次，P50）：V0 stage 61.0 ms、估算排队 43.8 MB/步 → V3 stage 1.9 ms、0 MB/步。
- **口径**：“MB/步”是按 attribute / texture 版本递增 × 区间大小得出的**估算**，不是 GPU 上传实测；Node 没有 WebGL，也不代表浏览器帧时间。
- H2 的 114 ms 等浏览器数字是转引，本包没有 H2 原始记录，不能独立复核。G4-P0-A 现在要求随报告提交原始逐帧 JSON。

## 问题四：Phase 2 “积压丢步”与确定性冲突 · 成立
- 原 ADR 写的“积压超限丢弃并计数”会让不同帧率的机器得到不同世界，与“同存档 + 同输入 + 同规则 → 同世界”矛盾。
- **修复**（ADR §2 / §3 / §9、路线图 P2-A、委托书 P2-A）：权威步一律不丢弃。负载超限时采用①游戏时间背压（游戏时钟只推进到水文完成处，HUD 显示实际倍速），或②分帧续算（一步拆到多帧，原子提交，完成前时钟不越过）。只有表现层可以降频或丢帧。
- 新增验收：同一存档、同一输入脚本在 20 / 60 / 144 fps 下推进相同游戏日，height / water / type / qi 逐字节一致。

## 问题五：命名与可复现性 · 成立
- 原 `ablate.mjs` 中 `E5_noHydrology` 是“完全停水文”，而文档中 E5 指静海规则，按名字调用会做错对照。
- **修复**：统一规范名 `V0_current` / `V1_noErosion` / `V2_seaSkipProto` / `V3_staticSeaStrict` / `V9_hydrologyOff`，文档内有别名对照表；委托书要求按规范名调用，并逐字复制 `lib/variants.mjs` 且记录 sha1。
- 所有脚本经 `lib/env.mjs` 读取 `INKBOX_ROOT`（缺失则退出码 2）；群岛 fixture 通过 `INKBOX_FIXTURE` 指定（`git show bfabe00:scripts/inkbox-g2-h3-archipelago-world.mjs`），加载时改写为指向 ROOT 的绝对导入，不改动 checkout。
- 已在一个不含缓存、不含结果的干净目录中验证可以运行。旧脚本（census / ablate / longrun / event）作为 R1 历史证据保留在 `experiments-r1/`，不再作为委托依据。

## 仍未解决
- 浏览器整帧与 GPU 收益（G4-P0-A）。
- 能蓄水的大坝 / 溃决场景。
- 沿海洪水退水加快、沟渠通海差异是否可接受（产品决策）。
- 现状的全图持续热力被去掉，是否影响山体观感（长期，需要美术 / 玩法确认）。
- 进入 v2 时的一次性全图归一化必须放在加载 / 升级时。
