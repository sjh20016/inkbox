# WX-C 改命权限与事务

继承 `b50623b18bdb2407a4efd1b837df3683a8305255`，保留 Profile v1 与存档 v11。自然模拟、普通改命、天道敕改共享正式人物和同一份 Profile，不建立第二份人生事实。

| 语义 | 正式入口 | 可改变的内容 | 不会产生的事实 |
|---|---|---|---|
| 自然因果 | Life、修炼、治疗、洞府、出生等既有消费者 | 按原规则支付代价、推进阶段、授予经历和资格 | UI 预览不能提交自然事件 |
| 常规改命 `player` | 命簿草稿→预览→提交 | 灵根、体质身份、本命卦、基础属性、性格、杂趣、合法主辅修与技能装配 | 不编辑状态、经历、恩义、永久成长、血脉资格、道种回执及治疗进度 |
| 天道敕改 `decree` | 显式命令→预览→提交 | 开脉、有限体质阶段、洗去已持有状态、赐血脉、血脉显隐 | 不伪造自然治疗、突破、稳定血脉、可遗传来源或一次性资源 |

普通体质表单只提交 `{id}`。替换为另一体质时从阶段0开始，不复制原体质治疗次数；选择同一身份保留最新自然进度。天灵根的原自然资格限制保留。普通玩家不能提交任意嵌套 Profile；自然模式 ChangeSet 不向公开编辑入口开放。

敕改当前采用自由观世，不收统一天机费用，不替换旧神力的代价规则。赐血脉默认初阶，`stable=false`、`inheritable=false`；不能凭一次敕赐获得自然定脉资格。UI 暴露开脉、洗状态、显隐及初阶赐血，较宽的阶段指令仅为有界 API。未来循缘模式应在独立策略中校验预算并把费用与敕改同事务提交；本轮不实现天机经济，也不把预算强加给自由模式。

草稿的可信基线保存在控制器内部；客户端 `draft.profile` 是观察数据。提交重新解析正式人物，在最新 Profile 上执行有限操作。无关受伤、治疗、突破事实、永久成长、恩义和道种消费保留；目标字段已变化则拒绝并要求刷新。主辅修只更新装配字段，不覆盖学习进度、战斗资源、冷却与血脉战斗账本。整体 `revision` 继续兼容，未新建互相独立的事实版本。

执行必须携带可信 `draftProof` 或经身份解析器验证的原 `token`。只有整数人物ID、revision或可序列化命令不能执行。原世界、位面实例、人物身体、存档恢复后的新对象及生命状态均重新校验。无绑定命令可做只读预览，但提交返回 `identity-binding-required`。同一草稿一次提交后作废；近期128条回执有界，超过窗口仍由版本和身份守卫拒绝旧命令。

每次成功敕改记录世界日、人物键、前后字段、敕改来源、传承资格是否涉及及进行中事务是否涉及。自然贯通、畏险转化、首次受恩与有代价回助分别保留真实引用。敕令开脉不增加 `treatments`、不改写 `lastTreatmentDay`，因此命簿能区分修行所得和天道敕令。

验证：`npm run test:wanxiang:c` 中 authority / ledger / save。包含八类绕过、144次合法操作、绑定身份重放、受控真实治疗/恩义/道种消费、贯通期间旧阶段敕改冲突、v11恢复。路径D的突破检查位于正式已提交事实边界；自然突破的产生频率由多种子画像验证，二者不混用。
