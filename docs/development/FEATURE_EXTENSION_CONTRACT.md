# 玩法原型接入约定 · 轻量 V0.1

本约定服务网页端多路线并行开发与 Codex 后续合流。它是**开发契约**，不是新增的插件引擎、运行时框架或已经实现的统一注册中心。适用角色词条/灵根/体质、命格、奇遇事件、遗物传闻、宗门和地点玩法。

## 一、源码责任和单一事实源

| 层 | 现有锚点 | 原型的安全职责 |
| --- | --- | --- |
| 世界与身份 | `world/World.js`、`world/*State.js`、`g1/characterIdentity.js` | 使用既有身份、同一世界坐标与已有实体；不可自己复制世界真相 |
| 正式规则 | `sim/`、`sim/advance.js` | 更新世界状态只能通过明确的模拟步骤；低频节拍在统一入口接线，不在 UI 的 rAF 增第二套时钟 |
| 随机与续跑 | `core/noise.js`、`sim/worldStreams.js`、`sim/runtimeState.js` | 不偷抽既有 RNG；新增随机需求需界定流、快照、跨界/存档语义 |
| 玩家观察 | `sim/biography.js`、`sim/journal.js`、`ui/` | 区分已证实事实与推断；人物、聚落、遗物、事件需可稳定回访 |
| 展现 | `render/`、`render3d/`、`ui/` | 只读世界快照，Canvas/Three 对同一语义保持一致；关闭面板不做额外昂贵刷新 |
| 存档 | `io/save.js`、`io/codec.js` | 先检查当前版本/行尾追加与可选块规则；旧档 fallback、坏块拒载、候选恢复是硬边界 |

**禁止**独立原型绕过 `advanceWorld` 另建推进循环，或将状态保存在仅 UI 可见的临时结构后宣称存档完成。不要为了试验添加每帧全图扫描。

## 二、一个原型的最小交付

1. **一句玩家可感知的循环**：触发 → 真实世界结果 → 玩家检视/回访。写清楚它改变什么、什么只负责表现、如何在几十到几百游戏年里重复/演化。
2. **隔离实现**：默认不启用；尽量在 `research/<prototype>/` 独立预览，或独立分支/Draft PR。不要在多个并行原型中共同改 `main.js`、`save.js`、`ui/railPanels.js`。
3. **规则输入输出**：声明读写字段、实体 ID/位面、事件触发时钟、上限与失效条件、RNG 来源、是否改变现有模拟、最坏情况成本。
4. **观察语义**：检视卡可回答“何时/为何发生、影响何人何地”；不要把推测或受控夹具事件记录成自然发生的世界史。
5. **存档清单**：写明需要持续化的字段、旧存档恢复策略、升级或拒载策略。由集成者根据当前正式 v11 协议决定可选块还是实体列尾追加，不能单独修改实体列中间布局。
6. **最低验证**：针对性规则测试、RNG/世界纯度、重复施放/撤销、存读档恢复、双 renderer 观察、行为不越界；只有确实涉及性能或长期生态才追加有限 GPU/长局专项。
7. **交接**：交付路径、基线 SHA、受影响文件、明确未做项、实际通过/未运行的检查、可回滚办法。浏览器截图不能替代真实模拟证明。

## 三、正式合流步骤（Codex 集成侧）

- 重新 fetch 最新 `main` 并核对开放 PR 与真实依赖；不得把候选旧 SHA 强行覆盖新主干。
- 先择取所需的**唯一行为增量**，不整分支重放老版 UI、存档或测试文件；同一核心文件由主集成者串行修改。
- 按顺序接入模拟事实 → 观察接口 → UI/Canvas/Three → 存档 → 定向测试；保留旧回退路径。
- 复杂度预算优先采用低频节拍、活动对象局部检索、聚合上限和只读视图；拒绝新增按每帧扫描全图的“方便实现”。
- 验证以合流后的实际提交运行 Fast/Heavy；有用户操作变更再做正式浏览器交互；GPU/800 年 Nightly 按真实影响与明确研究目标执行。
- 候选代码质量不过关时允许只合入数据定义、素材或玩法设计，不为清理 PR 列表接纳未完成逻辑。

## 四、本轮没有实施的事

未重构 `main.js`/`save.js`，未建立新运行时注册器，未更改当前可玩的技能、世界事件、随机流、存档字段或 UI。未来角色“灵根/体质/DNA 词条”可首先沿此契约做一个垂直切片，再决定是否出现真正重复且可抽取的共性。
