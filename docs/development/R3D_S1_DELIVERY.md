# R3D-S1 林海分卷 · 原型交付

## 实际基线与回退

开工重新 fetch 的 `main` 为 `4cf7f9fcda3a4ae77bf0e1ef2c20174bc591a2a7`。独立分支为 `perf/r3d-s1-vegetation-spatial-culling`，不合并主干。默认仍用旧全图批次；实验入口为 `inkbox.html?renderer=3d&forestCull=on`，去掉参数或使用 `forestCull=off` 后刷新即回退。

## 架构与修改范围

`VegetationLayer.js` 以派生世界坐标的 `floor(x/64):floor(y/64)` 组织稳定分区，每区只创建实际存在的 LOD 批次。原全局 `chooseLOD`、滞回、近景优先及配额分配保留。32×32 CPU 投影桶仍只用于预算优先级，与绘制分区独立；没有按分区复制全局配额。

树记录以 `cell → renderPartition → renderMesh → renderIndex` 定位本地槽位，`renderCount` 保留基础 billboard 的双槽语义。每次全局 LOD 变化只重写成员/变换变化的批次；无变化的镜头更新不写实例矩阵。局部地形编辑只改受影响实例及分区边界。成员资格变化、区域遮罩和美术切换走原有更新入口。

包围盒来自实际几何的 boundingBox 和 Float32 实例矩阵，额外覆盖山海 shader 的树冠 x/z 1.35 倍、y 1.12 倍以及最大描边位移。CPU 对分区盒作视锥判定，以父 Group.visible 跳过整个子树的 WebGL 绘制；L0 主体和墨线共享矩阵、颜色及父可见性。几何/材质/纹理由 Layer 持有，分区只管理实例对象与缓冲。

`Render3DAdapter.js`、`Render3DHost.js`、`stage/PlaneStage.js` 传递默认关闭的开关。`PlanePicker.js` 使用可见主体列表，排除描边；Adapter 的植被悬停签名使用 `pickRevision`，避免对增加的批次逐一序列化。`art/VisualScenarios.js` 的遮挡证据读取实际空间批次。新测试、npm 入口、Fast Gate 和打包显式脚本清单同步接入。

未改变树木派生、世界模拟、RNG、存档、Three.js 版本或正式美术资源。上界/幽冥继续使用现有 Stage profile，未生成新的凡界植被。

## 功能验证

本地 Node 24.11.1：`test:render3d:s1`、`test:render3d:m2c2a`、`test:render3d:m2c2b0`、`test:render3d:m2b`、`test:g5`、`test:g26`、`build`、`test:package` 均退出 0。打包首次因新测试未列入显式清单失败，补齐后540文件审计通过。新增有限 CPU 契约覆盖树身份与全局 LOD、相机剔除/恢复、无变化上传跳过、几何及 shader 边界、billboard 双槽、陡崖恢复与全新层矩阵等价、墨线共享、RegionMask、拾取与缓存、World 只读和三界释放。独立审查发现的贴地上传漏计已修复。

既有 `m2c2a1:forest` 浏览器归因矩阵未重复执行；本轮使用专门的四场景 S1 对照，并保留该既有入口。未运行 Nightly、800 年耐久或多设备矩阵。Fast/Heavy 的完整结果以 PR 当前提交的 CI 为准。

## 受控性能对照

正式样本在 AMD Radeon 610M / ANGLE D3D11 上通过，`test:render3d:s1:browser` 退出0。脚本为 `npm run test:render3d:s1:browser`，先运行 `npm run dev -- --port=4197`；可通过 `INKBOX_URL` 改地址。固定 `DENSITY_A`、seed 20260928、288×180、自然推进1800日后暂停、山海默认画风、1500×940 浏览器窗口、DPR 1，每模式每场景180个产品 RAF。相同世界摘要、LOD分配和操作路径成对验证。远近景截图经检查，没有明显缺树或描边错位；两次自有浏览器均完成进程与profile清理。

远景14/14分区可见，近景4/14；近景共有23个主体批次，7个活跃。近景提交树实例减少64.7%，全场提交三角形减少39.8%，这两个比例是实际绘制工作量而非 GPU 时间提升。静止远近景采样均零矩阵写入；移动时两路径同为113次必要LOD重排，实例写入735856 → 268418，上传标记339 → 938。说明局部批次减少写入量，却增加缓冲提交次数。

空间重建记录的是最后一次调用，而非全场平均：远景5.6、近景9.9、移动最后一次2.7、开窗返回最后一次6.8 ms。开窗/雕刻场景空间总矩阵写入22355、上传标记74，包含贴地更新；lodProbe单列LOD重排为9587/30，不能拿后者冒充全部更新成本。远景、近景、移动、开窗后 WebGL geometry/texture 数分别为33/7、49/8、49/8、60/13，新旧一致。近景植被总CPU实例缓冲容量3,040,000 → 3,178,488字节；其中分区模式挂载于场景的缓冲618,488字节，另有2,560,000字节旧模板CPU矩阵。GPU buffer对象数量随分区增长，显存字节未测。

报告保存于忽略目录 `reports/r3d-s1/browser/report.json`，远近截图同目录。原始报告记录源码 SHA-256、设备、样本数、World 摘要、实际主体/墨线 `onBeforeRender`、renderer.info、上传计数和专用浏览器清理结果。第一次沙箱启动因 Windows 进程查询权限失败；授权后的初轮完成，但启动菜单遮挡截图，因此修正菜单与引导状态后重跑作为正式样本。恢复工作时另一次启动因4197服务器已停止而超时，恢复服务并核实HTTP200后才开始正式样本；这些失败未混入性能数据。

`renderer.render()` 指 CPU 提交调用耗时，RAF 是浏览器帧间隔；本轮没有 GPU timer query，不提供 GPU 执行毫秒。Draw Calls / 三角形来自实际 WebGLRenderer.info，主体实例数来自实际渲染回调；spatialStats 是分区可见性统计。计数不使用毫秒单位。WebGL memory 仅资源数量；TypedArray 容量包括分区与 detached 模板，不能当 GPU 显存测量。

## 代价、裁决与后续

**CONDITIONAL**。密林近景与移动的受控样本受益，但全图远景 Draw Call 增加34.2%，RAF中位数16.8 → 22.1 ms（均值19.47 → 19.71、P95 22.4 → 23.1，短样本存在帧调度波动）。不据此全面启用。实验保持默认关闭，分区增加 Mesh、Draw Call、缓冲对象及边界维护成本。局部收益不能外推为整体渲染封板。未验证所有地图、显卡、DPR 2 与长期资源耐久；不自动推广到建筑、人物或其它场景对象。
