# P1 · G5 后剩余长帧专项

2026-10-19（Asia/Shanghai）。基线 `main` `f0c6bdf`，集成分支 `perf/p1-g5-longframe-integration`；接收 Opus 提交 `1d000ee067cc2b5082c7b36d53810f3c562abd92`，父提交与基线一致。模拟规则、水文、生态、存档格式、着色器与 G5 GPU/CPU 回退路径均未改动。P1 的 AMD Radeon 610M、Edge 155、广卷 512×320、DPR 1、模拟 ×2 指定场景已完成真实 GPU A/B 并验收通过；这不表示项目整体性能问题已经解决。Intel UHD 730 上 G5 时期约 1.07 s 长帧尚未通过同条件复测确认消除；DPR 2、其他显卡与长期负载仍未验证。

## 一、归因（事实）

以下根因隔离测量使用 Linux 无头 Chromium 与 SwiftShader 软件光栅，没有真实 GPU；旧 G5 报告中的约 1.07 s 长帧只反映 G5 当时状态，尚不能据此判断 P1 最终代码在 UHD 730 上的结果。

1. **SwiftShader 不能用于 GPU 判断。** 暂停状态下，683×384 的帧间隔约为 850 ms；即使缩到 160×90，每帧 GPU 同步仍约 830 ms，且与本帧有无上传无关。把每个缓冲合并成单段 `bufferSubData` 后，同步时间也没有变化。所以 UHD 730 上约 1 秒的长帧，无法在这里复现或确认是否已经消除。
2. **CPU 主线程**：512×320，老化 30 年，约 560 个实体；`gpu.render` 置空以隔离 CPU；固定 dt 16.667 ms，推进 30 秒（1799 帧，188 个水文步）。
   - 主线程帧耗时：p50 14.8 ms，p95 118.3 ms，p99 139 ms，最大 192 ms。
   - 分项：hover 拾取 35%，渲染侧 `update` 36%，模拟 28%。
   - cpuprofile 显示，three 的 `Mesh._computeIntersections` 对 32.6 万个地形三角形逐个暴力求交，**占全部主线程时间的 24%**。凡是静态拾取缓存失效的帧（所有水文帧，以及植被、火、生态导致的失效）都要付这笔成本，共 660/1799 帧，每帧 27–48 ms。
   - 植被成员重建会因 `heightChanged` 绕过 0.15 s 节流，在水文帧当场整图重建（12–38 ms），与地形和水面的更新成本叠在同一帧。
   - 每个水文步约有 480 次 `bufferSubData`，其中约 435 次是水面对角翻转逐个 quad 上传，每次 24 B。
3. 每个水文步约有 40% 的格子高度发生变化，包围盒覆盖整图，因此稀疏化脏区的收益有限，本轮不做。桥接扫描每帧约 2–5 ms（暂停时也会扫描）；微基准中，局部化与按行遍历没有收益，已撤回。

### P1-I 最终代码实测

同一隔离 Edge 155 会话先后打开基线 `main@f0c6bdf`（4182）和最终候选（4181），均为 1366×768、DPR 1、广卷 512×320、seed 20261018、相同相机与模拟 ×2；各预热 6 秒，再正常推进 30 秒。渲染器为 `ANGLE (AMD Radeon 610M, Direct3D11)`，画布 952×625。浏览器保持 visible，无页面错误；暂停后 1.5 秒日数变化为 0。截图和完整 JSON 留在本机忽略目录 `reports/local/p1i-edge/`，不进入发布包。

#### 真实 Edge 交互复核（不作为 A/B 计时数据）

在同一真实 Edge 上以广卷 512×320、模拟 ×2 检查了多点地形检视、桃坞王都屋舍与周隐灯身份拾取。上界及幽冥使用内置测试 Mask 固定视界区域，再以真实鼠标点选窗口内实体；检视分别返回上界格与幽冥法宝。窗外点击回到凡间拾取，没有观察到错位或跨位面误命中。另完成一笔小幅抬山，并实际执行撤销、重做；两个按钮可用态切换正确，高程回读有相应变化。交互时模拟持续推进，控制台无错误/警告，页面可操作；演进世界的界面 FPS 计数器约 8–12 FPS，此观察不是前述 30 秒 A/B，也不能作为目标 FPS 结论。

水面索引合并用同一 512×320 seed、187 个固定水文步，按 three `WebGLAttributes` 的 range 合并规则统计预期 `bufferSubData` 并单独计时 `WaterLayer.update`；这是 CPU 对照，不冒充真实驱动计时。

| 水面索引指标 | 逐 quad（最终保留） | 4096 索引间隙合并（已回退） |
| --- | ---: | ---: |
| 总上传调用 | 28117 | 10440（−63%） |
| 总上传字节 | 681048 | 111263448（约 163 倍） |
| 每步调用 P50 / P95 | 116 / 357 | 56 / 67 |

上传调用减少伴随约 163 倍索引字节和更慢的更新 CPU，无法证明总体执行收益，所以最终代码回退水面索引合并，保留射线拾取和植被错峰两项。当前非门禁拾取微基准为 512×320 中位数 0.07 ms（heightfield）对 11.78 ms（暴力求交），157.5 倍；正式门禁只检查结果严格一致。

## 四、其他设备复测方法

如需复测 UHD 730 或其他显卡，可在同一台机器用 Edge 打开 `inkbox.html?renderer=3d`，选择广卷（512×320）、种子 20261018、模拟 ×2，分别测 P1 起始基线 `main@f0c6bdf` 与包含 PR #29 的正式 `main` 各 30 秒，并比较 RAF P50/P95、Long Task 与 GPU 轨道。不要把单机短样本外推为所有硬件的固定帧率承诺。

## 五、回滚

对本分支的提交执行正常 `git revert`。仅回退拾取部分时，删除 `TerrainMesh.js` 中覆盖 `mesh.raycast` 的那几行即可，three 会回到原 `Mesh.raycast`。
