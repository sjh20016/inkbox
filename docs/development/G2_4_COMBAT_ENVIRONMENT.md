## 正式规则

`Life.attack()` 在实际扣血后调用模拟模块 `combatEnvironment.js`。施术者必须是活的凡间修士，等级至少 10（筑基），正式灵根元素中包含火；双方须属于同一世界，距离不超过既有近战范围 1.6，目标命中前有气血且本次确实损失气血。橙色表现风格不授予施术资格。

有适宜落点时，每人最多每 90 游戏日尝试一次。机会为 25%，用世界种子、双方 ID 和正式发生日的纯哈希计算，不增加 `Life.rng` 或生态流的抽取。失败机会也占用冷却；没有适宜地表则不施术。`lastFireCastDay` 表示最近一次尝试，默认 `-1e9`，追加到存档实体行 `row[69]`，旧档缺列时回填；新生、幽冥构造路径保持相同字段形状。

落点在目标附近九格内，初始最多引燃三格，80% 的成功尝试只点一格。地表须通过正式 `World.isWater()` 水面判据，且高于海平面安全边界、不是熔岩、有至少 25% 植被、湿度低于 70%、没有有效火势。逐格调用原 `ignite()`，强度为 0.45；只有比较点火前后 `World.fire` 确认新火，才成立引燃事实。初版只作用于已有完整生态时钟的凡间。

火灾随后完全由已有 `stepFire()`、`stepVegetation()`、覆盖层衰减和地形 dirty / 缓存接线推进。可蔓延、消耗植被、留焦土并复绿；这些过程不依赖观察面板、战斗墨痕或表现事件是否启用。未增加技能树、独立火势、伤害倍率或第二份历史库。

## 人物、史事与观察

每次确认新引燃只写一条 `combat-fire` 大事，复用 `World.milestone()` 的 600 条长窗口、400 条编年窗口及施术者的 32 条个人日志。文字仅说明真实参与者、发生坐标和已经点燃的格数，不把火头预先写成焚林结局。史料位置只保存 `x/y/plane` 标量；人物日志同样带位置，并归入传记「战事」。

短时战斗快照附带只读的确认引燃事实，独立于火色或雷色主表现。Canvas 在有权限的真实格画有限橙色余烬；Three 仅在引燃格的完整地表可见时为笔锋增加橙色细节。近讯「察看山河」、编年和大事记「查看」均先通过环境观察的当前权限校验，再定位到对应地表。旧的无坐标记录不生成定位按钮；读档和换世界仍会使会话对照及旧观察动作失效。

## 启动与试玩

```powershell
npm ci
npm run dev
```

Edge 打开 `http://127.0.0.1:4180/inkbox.html`；Three 使用 `?renderer=3d`。优先选择 200×128 或 288×180。观察有火灵根的筑基修士在山林附近交手；出现真实引燃后，从近讯或史事进入地表，记下此刻并推进时间，观察火灭、焦土和恢复。保存、另开世界再读档后，可从大事记重新定位；会话对照需重新记录。

自然施术受资格、接战、地表、冷却及机会共同限制，不保证开天即发生。单一聚焦回归可用 `npm run test:g24`；它使用正式 `Life.spawn()` / `Life.attack()`，选择固定种子可复现的施术日。

## 验证与边界

本地核心、G2、G2.3、G2.1 地形等价、UI、A1 资产、三界及保存等价通过。新增一个 `test:g24` 入口并接入 Fast，覆盖实际扣血、资格和地表的阳性/拒绝对照、89/90 日冷却、失败尝试、随机流计数、表现关闭、可复现性、正式生态后果、JSON 存档往返与旧行默认值。

原保存等价夹具只调用 `Life.step()`，会让新火永久存在。现改为唯一正式 `advanceWorld()` 入口推进凡间生态，保留原夹具的其他位面边界、固定种子和全部既有断言；120 年样本自然飞升两人，保存瞬间逐字段检查通过。未改产品参数、换幸运种子或删掉非空断言。历史 RNG 游标完整持久化仍未解决：本轮保证新增冷却与环境事实符合保存契约，不承诺读档后未来随机轨迹逐位一致。

真实浏览器为 Edge 155 / AMD Radeon 610M / D3D11，Canvas 与 Three 串行跑正式入口的 200×128 世界。固定夹具使用生成地表、原有人口及两个正式生成的筑基修士，由 AI 自行命中。在种子 244004 的（113，110），真实命中引燃一格；观察区火势最高达到 22 格，燃点植被从约 73% 降至约 9%，后续恢复至约 25%。关闭 Three 战斗墨痕仍得到同一环境后果；官方存读档、史事定位、位面切换与 GL 状态均检查，脚本/控制台无错误，自有浏览器及服务器清理确认。截图和原始诊断留在忽略的 `reports/g24/`。

Fast / Heavy 以该 Draft PR 的最终提交 Actions 为准。没有运行大型 GPU 耐久或全量 Nightly；原 G2 性能结论仍是 **PERF BLOCKED**。回滚可放弃本分支 / Draft PR，或在新分支反向提交本轮改动；已写入的新冷却尾列对旧读档逻辑仍为附加列，不需要重置主线或删除旧世界。
