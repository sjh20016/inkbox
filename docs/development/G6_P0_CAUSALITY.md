# G6-P0 · 亲友血仇

从最新 `origin/main@c45f9be2b74dbfa893c73bd6bcd74540a959cd97` 建立独立分支 `feat/g6-p0-fate-causality`。主线已含 G2.5/G2.6/G5/P1；本轮只接通模拟因果与原有观察记录，避开山海入画的材质、Shader、地形生成、美术资源和 UI 风格。

正式战斗致死后，幸存的父母、子女或强亲近的道侣/师门中人，会对真实凶手建立双向仇怨。父母子女按已有 `parentA/parentB` ID 判断，不按姓氏或整个宗族连坐；师门文案不臆定师徒方向。凶手与亲友都必须是同世界仍存活、未飞升、未到寿元的人类或修士。无个人凶手的天灾、寿终、宗门战殁及兽类捕食不进入此链。

仇怨实际写入原 `relations`，分数不高于 -60，由原有 `Life.findEnemy` 消费：再次相遇会接战，凡人、伤者和养伤者仍遵守原有逃离/休养规则。随机竞争不再将已成立的仇怨覆盖成普通宿敌。没有全图追杀、战力加成或额外强制战争。若幸存者与凶手本来还有非敌意关系，该主关系保留，本轮不处理复杂决裂。

真实斩杀仇敌且未获手下留情，才会写下“旧怨暂歇”。起因进编年史及双方个人日志，结局进胜者日志；两类经历重要性为 60，仍受原有 32 条个人日志上限约束。既有普通击杀、留命和外因死亡不会伪称复仇成功。

## 玩家如何观察

在 Canvas 或 3D 选中当事人，打开原有命簿：生平查看“因某人遇害……结下仇怨”，关系查看实名仇敌；后续真实斩杀会在生平及传记导出中留下结局。编年史可追踪遇害及结怨；关系在仇敌死亡后正常清理，个人记录继续保留。没有新增界面，记挂摘要没有另行扩展。

## 改动与验证

`sim/relations.js` 接起因并保留血仇类型；`sim/life.js` 记真实结局；`world/World.js` 的 `record` 可选第五参数仅控制个人日志重要性，原四参行为不变。新 `scripts/inkbox-g6-causality.mjs` 经 `npm run test:g6` 接入 Fast 和运行包清单；测试说明同步更新。

定向验证通过 G6 五组、core、干预回归 22 项、G2 战斗 9 组、G1 runtime 20 组、表现回归 127 项。覆盖同 tick 死亡清扫、mercy、无证据/已死/飞升者不归罪、非敌意关系保护、满额重要日志留存、存读档与命簿/传记只读。随机竞争守卫仍用原 5 次抽签；新死亡钩子不抽签。保存版本仍为 v11，无新持久字段，原存档对 `relation.since` 的恢复规则不变。新行为会进入原攻击/逃跑分支，后续世界线可自然分叉，不承诺新旧轨迹相同。

完整远端 Fast/Heavy 门禁保留，未反复运行无关 GPU、长帧或长期性能验收。存档等价曾启动后主动取消，不记为本地通过；新机制的存读档断言已直接覆盖，远端完整门禁结果另以当前交付提交为准。既有拜师方向与传功接线问题留待后续，本轮未顺带改动。回滚采用正常 revert 或放弃 Draft，不自动合并 main。
