# WX-C 效果性能与动态语义

复现：`npm run profile:wanxiang:effects -- --baseline=../inkbox-wanxiang-v02`。基线 checkout 为本地 `9581e97`，已核对其树 `fddae39924304d8113caece60b755e280aa6b015` 与远端 `b50623b` 相同。报告同时保存双方实际HEAD、树及dirty信息；最终交付只采用候选干净HEAD重跑的 `reports/local/wanxiang-c/effect-perf.json`。确切验收SHA见交付验收清单与PR最终说明。

环境：Windows 10.0.19045 x64，Intel i3-12100，Node v24.11.1。同机、同地图上下文、100/300/500实体受控夹具；并非自然人口恰好达到这些规模。无关系场景用已有乾卦，有关系场景用已有萃卦，先断言基线公共效果轴语义相同。双方各预热1500调用，每场景ABBA各5000调用，总计120000调用。候选静态/动态计时自身有开销，不从测量中隐去。

热点原因为每次情境计算重新建立功法编码/索引及目录解析。现统一 `manualIds.js` 为旧编码兼容的权威索引，仅缓存不可变目录编译；静态基础属性与目录效果先计算，动态条件及经历随后按实际上下文求值。不存在 `(entity,day,revision)` 整体效果缓存。健康、目标、装配技能、有效期、关系、位置和资源事实在同日变化也会重新判定。

受控样本中，无关系条件的平均调用约0.002–0.006ms，有关系条件约0.008–0.017ms；基线对应约0.013–0.027ms。具体均值、P95、静态/动态累计耗时和每次ABBA结果以最终JSON为准，不把这些短样本当作游戏帧率。每个5000调用样本中无关系条件全人口扫描为0，有关系条件仍为5000次；关系条件的成本仍随人口增加，尚未用全局依赖图或完整空间索引改写。

缓存命中/未命中由测量开关统计。预热后目录通常全部命中；没有人物效果缓存，所以人物缓存失效率不适用，也没有需要跨日失效的状态。模块重新加载自然替换目录编译缓存。状态/关系内容仍每次读取，不能因“缓存命中”提前跳过动态计算。

`test:wanxiang:c` 对同日健康、不同目标、潜隐休眠、期限和实际技能装配做正反检查；节卦同时验证御法、凝气击与回元的实际灵力支付，不能只减法术。新增consumer清单直接分派正式动作验证，没有靠静态搜索声明完成。

自然画像另记录 `process.cpuUsage()` 的用户+内核CPU时间、墙钟耗时及每世界年CPU。自然新版机缘更多、人口和行为已分岔，不能拿不同末人口的原始耗时直接推断优化百分比。基线首轮只保存墙钟时间，其字段不作为CPU证据。这里的同语义ABBA夹具才用于效果热路径前后比较。

未解决：关系条件仍有有界全人口查询；动态层仍创建局部集合；未证明极高人口长期性能，也未进行真实GPU性能封板。本轮没有为了性能缓存或省略真实情境。
